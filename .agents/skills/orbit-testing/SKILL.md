# 测试与验收

## 目标

测试证明「需求在公开行为上成立」，不是证明「代码按我写的方式运行」。

## 硬规则

1. 功能/修复与测试**同分支交付**，不允许先合后补。
2. **模块完成 = 模块测试完成**：模块对外可用时，必须有经过公开边界的模块级测试。
3. 修 bug 先写能复现的失败用例（红），再修到绿。
4. 不删除、不跳过、不放宽既有测试来换绿。

## 黑盒优先

从公开入口测：

- REST：真实 `listen` + `fetch`；
- MCP：真实协议调用；
- `OrbitAPI` / 浏览器 SQLite；
- 导出的 JSON 备份、导入后的账本；
- 页面可观察行为；
- 纯规则函数（取整、日期、tag 解析）可以单测，但断言输入→输出规则。

不要：

- 读源码正则，证明方法/常量/格式字符串存在；
- 断言私有字段、内部调用次数、日志文案、SQL 文本、对象 key 顺序；
- mock 掉真正要验证的那一层；
- 把当前实现的输出直接抄成期望值。

> `web/test/contract.test.js` 里有一部分读源码正则的契约断言，是历史遗留的白盒做法。修改相关模块时逐步换成公开接口/产物断言，**不要新增同类测试**。

## 防止「自己出卷自己批」

写测试前先脱离实现，从需求、文档、用户故事列验收点。提交前自问：

1. 如果实现写错了，这个测试会失败吗？
2. 它验证的是需求，还是我刚写的实现？
3. 期望值有独立来源吗（手算、文档、不变量、另一条路径）？
4. 失败路径和边界覆盖了吗？
5. 换一种内部实现，测试还成立吗？

### 好/坏例子

| 坏 | 好 |
|---|---|
| 读源码断言 `BACKUP_FORMAT = '...'` | 导出 → 解析 JSON → 校验格式/版本 → 再导入 → 账目、标签、金额一致，原账本不变 |
| 把运行时输出复制成 `deepEqual` 期望值 | 断言各维 Σ = 总额、「未分类」计入；换一组数据仍成立 |
| mock 掉 service 后断言 repo 被调用 | 真实内存库 + 真实 service/HTTP，断言最终数据和错误码 |
| 只测 happy path | 同时测拒绝路径：跨账本、重复导入、事务失败 |

## 断言什么

优先：

- **不变量**：每维 Σ = 总额；账本隔离；单事务回滚；导入导出往返；迁移可重放。
- **业务结果**：用户能看到、能继续操作的状态。
- **契约**：HTTP 状态码、错误码、schema 版本、备份格式、金额精确到分。

避免：

- 无关的顺序、自动 id、时间戳、内部结构、精确错误文案。
- 只断言「函数被调用」而不看结果。
- 为了好写而缩小需求范围。

## 测试层次

| 层 | 位置 | 重点 |
|---|---|---|
| 单元 | 模块内纯规则 | 取整、日期、tag 解析、边界 |
| 模块/集成 | `server/test/`、`webapp/test/` | service + 真实 DB、REST/MCP 全流程、导入导出往返 |
| 端到端 | `web/test/`、`verify:web` | 记账 → 刷新 → 统计、备份恢复、关键 UI 路径 |

## 账本必测边界

- 空账本、空月、没有任何 tag；
- 0 分、1 分、跨分取整；
- 跨账本引用 tag（应拒绝且不落库）；
- 重复导入同一备份（每次新账本、互不影响）；
- 跨月/跨年/时区边界、「今天」；
- 事务中途失败（账目、tag、关联全部回滚）；
- 删除被引用的 tag（应拒绝）；
- 收入/支出的统计隔离；
- 旧库迁移到最新版后数据不丢、约束仍生效。

## 运行与登记

- 全量：`cd server && npm test`（固定顺序串行）。
- **新增测试文件必须加进 `server/package.json` 的 `test` 脚本**，否则 CI 不会跑。
- 用临时目录/内存库；涉及「今天」的用例固定时钟；不提交真实个人账本数据。
- 涉及 `web/`、`webapp/` 改动时跑 `npm run build:web`；端到端 `npm run verify:web` 只在本地跑（需要 GUI）。
- 涉及桌面壳层/打包改动时，对应平台构建必须过：Linux 用 `npm run dist:linux`（AppImage + deb），CI 的「Linux 安装包构建」是必过项。
- Linux 运行冒烟：`npm run verify:linux` 在 Electron 主进程里起真实 HTTP + SQLite（无窗口），CI 与 CD 都会跑。

## 评审清单

- [ ] 每个需求点至少一个公开入口用例
- [ ] 失败路径和边界已覆盖
- [ ] 期望值可独立推导，不是从运行结果复制
- [ ] 没有源码正则、私有字段、调用次数断言
- [ ] 没有 mock 掉被测层
- [ ] 新增测试文件已登记到 `test` 脚本
